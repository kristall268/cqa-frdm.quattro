# CQA-FRDM — Frontend нұсқаулығы

> **Claude-ға:** Бұл файл + `CONTRACT.md` — жалғыз дереккөз. PDF керек емес.
> Plain HTML/CSS/JS ғана: React, Vue, jQuery, npm, build ЖОҚ. Тек `frontend/` папкасын өзгерт.
> API-ді өзің ойлап таппа — тек CONTRACT.md §4–5 ішіндегі endpoint/DTO.

## 0. Не жасаймыз
Оператор чаттарын AI бағалайтын веб-интерфейс. Демо жолы (5 мин):
**тізім → диалог ашу → AI бағасы (балл, түсіндірме, дәлел-репликаға секіру, N/A, итог) → апелляция → тексеруші шешімі → жаңа итог → чек-лист критерийін өзгертіп, қайта бағалау.**

## 1. Іске қосу
```
cqa-frdm/
├── backend/          (досың жазып жатыр, :8080)
└── frontend/         (сен)
    ├── index.html
    ├── css/cqa.css
    ├── js/config.js          API_BASE, USE_MOCK
    ├── js/api.js             fetch-обёртка + mock режимі
    ├── js/router.js          hash routing
    ├── js/ui.js              ортақ: toast, loader, badge, escapeHtml
    ├── js/conversations.js   #/  тізім
    ├── js/card.js            #/c/{id} транскрипт + аудио + бағалау панелі
    ├── js/checklist.js       #/checklists редактор
    ├── js/appeals.js         апелляция формасы + #/appeals тексеруші
    └── mock/
        ├── conversations.json
        ├── conversation-p1-ru-001.json
        ├── checklists.json
        └── evaluation-1.json
```
Іске қосу: VS Code → Live Server (порт 5500) немесе `cd frontend && python -m http.server 5500` → `http://localhost:5500`.

`js/config.js`:
```js
window.CQA = window.CQA || {};
CQA.config = { API_BASE: "http://localhost:8080", USE_MOCK: true }; // backend дайын болса false
```

## 2. Міндетті ережелер
1. Барлық UI `<div id="cqa-root">` ішіне салынады. CSS класы тек `cqa-` префиксімен, `body`/`html`-ге глобал стиль жоқ (кейін Dynamics 365-ке қосылады).
2. Бір ғана глобал объект: `window.CQA = { config, api, ui, router, conversations, card, checklist, appeals }`. Скрипттер `<script defer>`, ES-модуль/импорт қажет емес.
3. Сервер мәтінін тек `textContent` / `escapeHtml` арқылы шығар (XSS).
4. Әр сұрауда: loader → нәтиже, қате болса `{error,message}`-ті toast-пен көрсет, бет құламасын.
5. Транскрипттің `timestamp`, `speaker`, `text` мәндерін өзгертпей көрсет. Реплика ID = массив индексі (0-ден).
6. Ешқандай API кілт/құпия frontend-те жоқ.
7. Дизайн: таза, қатаң, корпоративті (ақ фон, бір акцент түс, кесте/карточка). Мобильді міндетті емес, 1280px+ жеткілікті.

## 3. API (CONTRACT.md §5-тен қысқаша)
| Қайда қолданылады | Сұрау |
|---|---|
| Тізім | `GET /api/conversations?groupId=&language=&channel=` |
| Импорт батырмасы | `POST /api/datasets/import {"groupId":"DEV"}` |
| Карточка | `GET /api/conversations/{id}` |
| Чек-лист таңдау/редактор | `GET /api/checklists`, `GET /api/checklists/{id}`, `POST /api/checklists {"name","criteria"}` |
| Бағалау | `POST /api/evaluations {"conversationId","checklistVersionId"}` |
| Соңғы бағалар | `GET /api/evaluations?conversationId=` |
| Бәрін бағалау | `POST /api/evaluations/batch {"groupId","checklistVersionId"}` |
| Апелляция | `POST /api/appeals {"evaluationId","criterionId","comment","evidenceIds"}` |
| Тексеруші | `GET /api/appeals?status=OPEN`, `PATCH /api/appeals/{id} {"decision":"CONFIRMED"|"CHANGED","newAnswer","newIsNa","reason"}` |

DTO пішімдері — CONTRACT.md §4 (`Conversation`, `Criterion`, `ChecklistVersion`, `CriterionResult`, `EvaluationResult`, `EvaluationDto`, `AppealDto`). Карточкада әрқашан `EvaluationDto.final` көрсетіледі, ал `original` апелляция болса қатар шығады.

## 4. Mock деректер (backend-ті күтпеу үшін)
`api.js` `USE_MOCK=true` кезінде GET-терді `mock/*.json`-нан оқиды, POST/PATCH-ті жадта имитациялайды (мысалы, апелляция шешімінен кейін `final` жаңарады). `mock/conversation-p1-ru-001.json` мысалы:
```json
{ "id":"p1-ru-001","groupId":"DEV","channel":"agent chat","language":"RU","audioUrl":null,
  "transcript":[
    {"timestamp":"00:00","speaker":"system","text":"Чат начат"},
    {"timestamp":"00:05","speaker":"client","text":"Здравствуйте, не могу вывести деньги"},
    {"timestamp":"00:40","speaker":"operator","text":"Здравствуйте! Меня зовут Айгерим. Подскажите номер счёта?"},
    {"timestamp":"01:10","speaker":"client","text":"12345"},
    {"timestamp":"02:00","speaker":"operator","text":"Вывод в обработке, поступит в течение 1 дня. Чем-то ещё помочь?"},
    {"timestamp":"02:20","speaker":"system","text":"Чат закрыт"}]}
```
Тағы 1 KZ чат және 1 `voice call` (timestamp ISO, мысалы `"2026-05-12T10:00:03+05:00"`, `audioUrl` бар) қос. `evaluation-1.json` — 8 критерийдің бәрі бар `EvaluationDto` (кемінде бір N/A, бір "NO" + `checkedRange`, c8 FLAG).

## 5. Қадамдар (ретімен; әр қадам — Claude-та жаңа чат)

### Қадам 1 — Каркас (30 мин)
Промпт: *«FRONTEND.md және CONTRACT.md оқы. 1-қадамды жаса: index.html, css/cqa.css, js/config.js, js/api.js (mock режимімен), js/router.js, js/ui.js және mock/ файлдары. Хедерде навигация: Диалогтар / Чек-листтер / Апелляциялар.»*
Дайын: беттер hash арқылы ауысады, `CQA.api.get('/api/conversations')` mock қайтарады.

### Қадам 2 — Диалогтар тізімі `#/` (45 мин)
- Кесте: ID, канал (чат/қоңырау иконкасы), тіл, алғашқы реплика (`preview`), хабар саны, соңғы балл (түсті badge: ≥85 жасыл, 60–85 сары, <60 қызыл), грубая ошибка 🚩, статус FAILED.
- Сүзгілер: тіл RU/KZ/EN, канал, мәтін іздеу (клиент жағында).
- Жоғарғы панель: `group_id` input + **Импорттау**, чек-лист нұсқасы select + **Барлығын бағалау** (batch, кейін әр 5 сек тізімді жаңарту, 2 мин немесе бәрі бағаланғанша).
- Жолды басу → `#/c/{id}`.
Дайын: сүзгі жұмыс істейді, loader/бос/қате күйлері бар.

### Қадам 3 — Диалог карточкасы `#/c/{id}` (1,5 сағ) — ЕҢ МАҢЫЗДЫ
Екі баған.
**Сол жақ — транскрипт:** әр реплика `<div class="cqa-msg cqa-msg--{speaker}" data-msg="{i}">`: `#i`, timestamp, рөл, мәтін. Клиент сол жақта, оператор оң жақта (чат стилі), bot/system сұр, кішірек, ортада. Voice call болса жоғарыда `<audio controls src=audioUrl>`.
**Оң жақ — бағалау панелі:**
- Чек-лист нұсқасы select + **Бағалау** батырмасы (loader «AI талдап жатыр…»).
- Үлкен итог: `87.50 / 100` (null болса «Итог есептелмейді — қолданылатын критерий жоқ»). Грубая ошибка болса қызыл баннер + себебі. Модель және құн: `gpt-x · $0.0021`.
- Әр критерий карточкасы: атауы, жауап (Иә/Жоқ/N/A/«15 из 20»), балл/салмақ (`15 / 20`), түсіндірме, дәлел чиптері `#4`, `#6`, `checkedRange` болса «Тексерілген аралық: #3–#8», N/A болса себебі сұр түспен. Батырма **Апелляция**.
- Апелляция болса: «Бастапқы: Жоқ (0) → Финал: Иә (10)», тексеруші себебі; итогта «Бастапқы 72.00 → Финал 82.00».
**Дәлелге секіру:** чипті басу → `scrollIntoView({block:'center'})` + 2 сек сары подсветка; `checkedRange` — аралықтағы репликалардың сол жағында түсті жолақ. Voice call: `audio.currentTime = (Date.parse(ts[i]) - Date.parse(ts[0]))/1000; audio.play()` (чатта MM:SS — аудио жоқ, тек скролл).
Дайын: кез келген дәлел дұрыс репликаны көрсетеді; FAILED бағаны «AI жауабы жарамсыз, қайта бағалаңыз» деп көрсетеді.

### Қадам 4 — Апелляция және тексеруші (1 сағ)
- Карточкадағы **Апелляция** → модаль: критерий атауы, қазіргі баға, комментарий (міндетті), дәлел таңдау (транскрипттен реплика нөмірлері checkbox). Сақтау → `POST /api/appeals` → «Апелляция жіберілді».
- `#/appeals` (тексеруші): ашық апелляциялар тізімі. Біреуін ашқанда: диалог ID (сілтеме), критерий, AI бағасы + түсіндірме, клиент комментарийі, дәлел реплика мәтіндері. Екі әрекет: **Растау** немесе **Өзгерту** (критерий типіне сай: Иә/Жоқ, шкала мәндері select, N/A checkbox тек `naAllowed`) + себеп (міндетті) → `PATCH`. Нәтиже: «Жаңа итог: 82.00».
- Хедерде ашық апелляция саны badge.
Дайын: апелляция → шешім → карточкада бастапқы мен финал қатар тұр.

### Қадам 5 — Чек-лист редакторы `#/checklists` (1 сағ)
- Сол жақ: нұсқалар тізімі (`default v1`, `v2`…, күні).
- Оң жақ: таңдалған нұсқаның критерийлері кестесі, әр жолы өңделеді: `id` (жаңада авто `c9`…), атауы, секция, ереже мәтіні (textarea), тип (BINARY / SCALE / FLAG), салмақ, `naAllowed` + `naCondition`, SCALE болса ступендер тізімі (value + label, қосу/өшіру).
- **Критерий қосу**, **Өшіру**, **Жаңа нұсқа ретінде сақтау** (`POST /api/checklists`, ескі нұсқа өзгермейді).
- Валидация (клиентте): салмақ > 0 (FLAG үшін 0), SCALE-да кемінде 2 ступень, атау бос емес. Салмақтар қосындысын көрсет (ақпарат үшін, 100 болуы міндетті емес — backend нормалайды).
Дайын: критерийді ауыстырып сақтау → карточкада жаңа нұсқа select-те → бағалау жаңа критериймен шығады. **Бұл 23-сағаттағы бақылау тапсырмасы — кодсыз істелуі керек.**

### Қадам 6 — Жылтырату (уақыт қалса)
Тілдер RU/KZ/EN мәтінмен тексеру; ұзын транскрипт скроллы; бос күйлер; хедерде «DEV / группа» индикаторы; шағын статистика (орташа балл, грубая ошибка саны) тізім үстінде.

## 6. Backend-пен интеграция
1. `config.js` → `USE_MOCK:false`.
2. Backend-те CORS `http://localhost:5500` үшін ашық болуы керек (досыңның `CorsConfig`).
3. Сәйкес келмесе — **DTO-ны frontend-те өзгертпе**, досыңа айт, CONTRACT.md бойынша кім дұрыс екенін шешіңдер.
